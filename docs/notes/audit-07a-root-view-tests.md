### Key Findings at a Glance

1. **7,550 Lines (67% of `view_test.go`) Are Static `closure` AST/Types Rules Tested Through End-to-End Subprocess `engine.newView` Calls**:
   - From [line 3687 to line 9866](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L3687-L9866) (plus lines 10509–10754), 24 top-level test functions containing **275 `t.Run` subtests** test static shared-dynamic-state rules (`REQ-closure-shared-dynamic-state*`): carrier-escape discharges, init-only registration, mutation-shape classification, `sync.Pool` / `reflect.TypeOf` / `fmt.Errorf` / `errors.New` object-closed rules, cross-package re-exports, single-subject / package-process reachability scoping, and literal-borne site foreclosures.
   - [`TestCarrierEscapeDischarges`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L3803-L8259) alone is **4,457 lines long** with **143 sequential `t.Run` subtests**. Every single subtest calls `writeModuleTree(t, ...)` to materialize a multi-package Go module on disk and `captureCheck(t, dir, ...)` to construct a full `engine` and `Snapshot` view—spawning multiple `go` toolchain subprocesses (`go list`, `go env`, `go/packages` driver)—just to verify a pure AST/type-checker predicate in `internal/closure`.
   - Because each subtest spawns real `go` commands, 118 of the 122 tests in `view_test.go` have `if testing.Short() { t.Skip(...) }`, leaving almost zero coverage in `-short` mode while making full runs painfully slow.
2. **In-Memory `go/parser` + `go/types` + `go/ssa` Harness Eliminates ~95% of Subprocess Overhead**:
   - None of the 275 shared-dynamic-state subtests (nor the 25 single-expression observability/purity classification tests in L899–1765) depend on the `go` CLI driver, filesystem module layout, or OS environment guards. They can run in **< 50ms total** via an in-memory multi-package `go/parser` + `go/types` harness (and in-memory `go/ssa` for RTA observability proofs) with **zero subprocess spawns** and **no `testing.Short()` skips**.
3. **White-Box State-Machine & Lifecycle Tests Can Use a Synthetic Loader Stub**:
   - Over 45 tests in `view_test.go` test `Snapshot` (`view.go`) state-machine invariants: context cancellation at lock/observation/analysis boundaries, `Validate` sealing (`ErrViewSealed`), `Sibling` transaction isolation, deferred check close (`withDeferredCheckClose`), runtime-input manifest phase deduplication (`view.runtimeCurrent`), and analysis-budget straddling across paired passes (`viewTestHooks`).
   - These tests already inject hooks (`viewTestHooks.observe`, `viewTestHooks.beforePreciseAnalysis`, `viewTestHooks.analysisBound`, `viewTestHooks.beforeDischarge`, `view.runtimeCurrent`), yet still write a dummy module (`package view; func F() int { return 1 }`) to disk and run `go/packages` on every test. Feeding `Snapshot` pre-built in-memory `closure` facts makes all `Snapshot` state-machine tests instant, deterministic unit tests.
4. **Direct Overlaps and Redundancies Identified**:
   - [`TestNewViewRejectsSourceChangeDuringConstruction`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L780-L804) is a strict prefix/subset of [`TestConstructionDriftNamesTheChangedFile`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L810-L838) (identical fixture, identical `withAssumePure` mid-construction mutation of `view.go`; the latter checks both `errors.Is(err, ErrViewChanged)` and the filename in the error string).
   - [`TestDotlessModuleKeepsStartupRefusals`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L10328-L10360) and [`TestDotlessModuleFlagAndTestMainSoundness`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L10367-L10439) test the exact same dotless-module `StandardLibrary` classification contract across 3 subcases and belong in a single table-driven test (or in-memory package-metadata unit test).
   - `view_test.go` defines two nearly identical `capture` closures in [`TestSingleSubjectDirectiveDischarges`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L9396-L9416) and [`TestReachabilityScopedDischarge`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L9517-L9536), alongside top-level [`captureCheck`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L8393-L8412).

## 3. Architectural & Structural Critique of the Root View Test Suite

### 3.1 The Subprocess Tax: Testing AST/Type-Checker Predicates via `go/packages` Subprocesses

The single biggest architectural flaw in `view_test.go` is **layer conflation**:
- `gofresh` has a clean conceptual separation between:
  1. **Source & Type Analysis (`internal/closure` and `internal/observability`)**: Pure static analysis over `*ast.File`, `*types.Package`, `*types.Info`, and `*ssa.Package`.
  2. **Snapshot / View Transaction State Machine (`view.go`)**: Coherent two-pass construction, drift comparison (`ErrViewChanged`), sealing (`ErrViewSealed`), sibling derivation (`Sibling`), deferred check close, runtime-input window bracketing, and budget/cancellation handling.
  3. **Toolchain / Filesystem Integration (`go/packages` loader, `go env`, `go.work`, `GOMODCACHE`, persistent memo store)**.
- Yet `view_test.go` tests **all three layers through the outermost `engine.newView` entry point**, writing temporary modules to disk (`writeViewModule` / `writeModuleTree`) and invoking `packages.Load` (which spawns `go list` / `go env` subprocesses) for **every single test case and subtest**.

### 3.2 Special Case: `TestGeneratedProtoClusterDischarges` (L9680–9811)

[`TestGeneratedProtoClusterDischarges`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/view_test.go#L9680-L9811) is a prime example of unnecessary subprocess heavy lifting:
- To test that `internal/closure` checks two conditions—(1) the file header matches `generatedProtoHeader` (`protoc-gen-go` or `protoc-gen-go-grpc`) and (2) the imported runtime package's module version matches the audited version (`google.golang.org/protobuf@v1.36.11` or `google.golang.org/grpc@v1.82.1`)—the test:
  - Allocates a temporary `GOMODCACHE` and a file-backed `GOPROXY`,
  - Materializes module zip archives via `writeFileProxyModule`,
  - Spawns `exec.Command("go", "mod", "tidy")` **6 separate times**,
  - Spawns `engine.newView` (`packages.Load`) **6 separate times**, and
  - Spawns `exec.Command("go", "clean", "-modcache")` in `t.Cleanup`.
- All of this tests a module-version string comparison on the package metadata passed into `closure`! With an in-memory package loader that populates `Module: &packages.Module{Path: "google.golang.org/protobuf", Version: "v1.36.11"}`, all 6 cases run in **< 1ms** with zero `go mod tidy` or `GOPROXY` setup.

## 4. Target Testing Architecture: Replacing 11,235 Lines with a Fast, Tiered Framework
