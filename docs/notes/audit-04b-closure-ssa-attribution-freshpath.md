## 1. Executive Summary & Architectural Overview

The four files in Scope 04b form the core SSA-based reachability, provenance, dynamic-value closure, and side-effect classification engine in `package closure`:

1. **[`closure/attribution.go`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go)** (3,652 lines) bridges the bitmask Rapid Type Analysis (`closure/internal/rta`) and the per-subject Tier-2 SSA analyzer. It:
   - Manages 64-subject bitmask batches (`subjectMask = uint64`), with package-scope probing (`probePackageScope`) and binary bisection (`splitAttributed`) when `rta.Analyze` encounters an `"unsupported analysis shape"`.
   - Performs whole-program caller reference enumeration (`enumerateCallerReferences`) and open-signature root closure (`subjectEnumerationClosure`) so functions/methods with dynamic parameters or struct receivers can be analyzed as closed-world when all call sites and struct field stores in the program are statically enumerable and closed.
   - Runs iterative RTA + provenance loops to discover and root `testing.T.Cleanup` and `testing.F.Fuzz` callbacks (`collectTestingHarnessCallbacks`).
   - Projects bitmask RTA results into per-subject `attributedReachability` sets (`subjectFunctions`, `startupFunctions`, `testMainFunctions`, `cleanupFunctions`, `rootedExtraFunctions`) and computes binary-wide post-init reachability unions (`binaryReachableUnion`) for `REQ-closure-shared-dynamic-state-reachability`.
   - Hosts the exported `SignatureOpenWorldTerm`, `WalkDynamicCarrier`, `TypeParamBoundsAwayFromDynamic`, and `AuditedAtomicPointerElem` predicates shared with root package `gofresh`.

2. **[`closure/analyzer.go`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go)** (2,140 lines) implements the Tier-2 SSA/AST reachability and external-effect scanner (`tier2Base` and `tier2Analyzer`). It:
   - Builds an immutable per-program AST/types/linkname index (`tier2Base`, `pkgIndex`).
   - Walks RTA-reached functions (`scanFunction`, `scanInstruction`, `scanCall`, `scanValue`) and AST declaration references (`drainObjects`, `addObject`, `scanNodeRefs`) to collect `types.Object`s (used for fine-grained AST declaration pruning via `funcDeclKey` and `unreachedASTDecls`) and classify `externalEffect`s or request closure widening (`requestWiden`).
   - Admits subject-determined dynamic dispatches (`dispatchAdmitted`, `subjectDeterminedInvokes`) and classifies direct calls (`classifyCalleeEffect`) against Class-B effects, unaudited standard-library fallbacks, `flag` provenance, `os.OpenFile`/`syscall.Open` flags, `time.Unix(...).UTC()/In(FixedZone)` chains, and `fmt.Fprint*` in-memory writer sinks.

3. **[`closure/freshparam.go`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/freshparam.go)** (489 lines) defines `freshParamAnalysis`, which originally carried `t.TempDir()` fresh-path capabilities across static function parameters (`paramArgFreshMemo`, `paramUsesObservableMemo`, `boundaryCrossingObservable`), and has since grown into the **kitchen-sink state bag** (51 struct fields) for all interprocedural dynamic-value, struct-field-store, Tarjan SCC lowlink, and memoization state used by `freshpath.go` and `attribution.go`.

4. **[`closure/freshpath.go`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/freshpath.go)** (5,177 lines) contains two distinct subsystems cohabiting in one file:
   - **Lines 18–1038**: The observability and fresh-path / guard-pinned-path / `os.File` / `os.ReadDir` dataflow grammar (`observableCallEffect`, `freshPathValue`, `observableFreshPathUses`, `guardPinnedPathValue`, `observableOpenResult`, `observableReadDirResult`, `fileValueFromAdmittedOpen`).
   - **Lines 1040–5177**: A massive (~4,140-line) backward/forward SSA abstract interpreter (`walkDynamicValue`, `walkDynamicValueUncached`, `staticCallResultDynamicValue`, `calleeResultDynamicValue`, `closedInvokeTargets`, `resolveConcreteMethodTargets`, `walkLoadCellReferrersWithFP`, `walkMakeSliceIndexedStoresWithFP`, `walkMakeMapValuesWithFP`, `walkMapSliceReadsWithFP`, `attributedParameterArgs`, `attributedFreeVarBindings`, `inMemoryFormattedSink`, `isHarnessContextCall`) that proves whether dynamic SSA values (interfaces, function values, closures, slices, maps, structs, cells, parameters, call results) are closed under the subject's flow and collects their concrete runtime types and target `*ssa.Function`s.

## 4. Architectural Analysis by Domain Mechanism

### 4.1 SSA Instructions, AST Object Drain, and Two-Tier Classification (`analyzer.go`)

[`closure/analyzer.go`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L150-L794) implements a dual-representation (AST + SSA) pass over reachable functions:
1. **AST `TypesInfo.Uses` Drain ([`analyzeTier1`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L353-L553), [`drainObjectUses`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L614-L742))**:
   - Before inspecting SSA instructions, `analyzeTier1` maps every reachable `*ssa.Function` back to its `*ast.FuncDecl` or `*ast.FuncLit` (`funcDeclByPos`, `funcLitByPos`), collects nested `*ast.FuncLit` regions to exclude (`collectNestedFuncLits`), and drains `pkg.TypesInfo.Uses` for every identifier within the function's `[start, end]` token range (`objectUsesInRange`).
   - Why? Because constants, type conversions, and some package-level variable references may be constant-folded or lowered in SSA, or need AST-level inspection (such as [`isConstantPureTimeWaitCall`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L2020-L2139) which inspects AST `CallExpr` arguments to `time.Sleep`, `time.After`, `time.Tick`, `time.NewTimer`, `time.NewTicker`).
2. **SSA Instruction Scan ([`scanSSAFunction`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L796-L950))**:
   - Walks `fn.Blocks` -> `block.Instrs` for every reachable function (except generic origin templates skipped by [`skipOriginScan`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L343-L350), whose concrete instantiations `fn.Origin() == root` are scanned instead).
   - Rejects `*ssa.Go` (`"go statement"`), `*ssa.Send` (`"channel send"`), `*ssa.Select` (`"select statement"`), and channel receive `*ssa.UnOp{Op: token.ARROW}` (`"channel receive"`), unless the channel receive is the direct result of a constant-duration `time.After`/`time.Tick` or `t.C` field read from `time.NewTimer`/`time.NewTicker` ([`isConstantPureTimeChannelReceive`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L555-L612)).
   - Classifies static calls via [`classifyCalleeEffect`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L952-L971) and dynamic calls (`call.Common().IsInvoke()` or non-static `*ssa.Function` value) via [`dispatchAdmitted`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L1058-L1119).
3. **Subject-Determined Re-Evaluation Loop ([`analyzeTier1:482–534`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/analyzer.go#L482-L534))**:
   - Because `scanSSAFunction` runs *once per reachable function* (using `fp := newFreshParamAnalysis(res.Program, pkgByPath, opts.Audited, nil, nil)` without subject attribution), any dynamic call that is only closed when restricted to a *specific subject's* attributed call sites (`subjectDeterminedInvokes`) fails during the shared function scan, recording `fnReasons[fn] = "dynamic dispatch"` and `fnHasNonDispatchReason[fn] = false`.
   - Then, for each subject `s`, if all reachable functions with reasons for `s` have `!fnHasNonDispatchReason[fn]`, `analyzeTier1` constructs a subject-specific `subjFP := newFreshParamAnalysis(..., s.Reachable, s.Summary)` and re-checks every dynamic call in `fn` via `dispatchAdmitted(..., subjFP)`.

### 4.2 Call Graphs, RTA Batching, Bisection, and Provenance (`attribution.go`)

[`closure/attribution.go`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L1-L3652) is responsible for determining *which* functions are reachable from each subject function (`Test*`, `Benchmark*`, `Fuzz*`, `Example*`, `TestMain`, or exported entrypoints) and *which* call sites / closure bindings / struct stores can be attributed to that subject:

1. **Bitmask RTA with Iterative Harness Callback Discovery ([`attributedReachableSets`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L35-L273))**:
   - Processes subjects in batches of up to 64 (`batchSize = 64`), assigning each subject a bit `uint64(1) << i`.
   - Builds a `seedMap` mapping each subject root (plus `init` functions and package-level `var` initializer functions via [`collectVarInitSeeds`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L817-L907)) to its bitmask.
   - Runs `rta.AnalyzeBitmask` in a `for` loop (`attribution.go:108–150`) that calls [`collectTestingHarnessCallbacks`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L363-L411) after each RTA pass to discover functions passed to `testing.T.Cleanup`, `testing.B.Cleanup`, `testing.F.Cleanup`, or `testing.F.Fuzz` inside newly reached functions, adding them to `seedMap` until fixpoint.
   - Also runs a separate `initRes := rta.AnalyzeBitmask(initSeedMap, ...)` pass (`attribution.go:154–172`) to compute `startupBase` via [`provenanceReachableStartup`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L2969-L3033).
2. **Whole-Program Cross-Pollution vs. Subject Bisection ([`attribution.go:183–243`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L183-L243))**:
   - In standard RTA, runtime types instantiated by Subject A enter a shared global interface dispatch table and can wake up interface methods called by Subject B.
   - Rather than tracking per-bitmask runtime types inside `rta.AnalyzeBitmask`, `attributedReachableSets` runs a heuristic filter [`hasCrossSubjectDynamicTarget`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L618-L654): if a subject's reachable set contains a dynamic call target `callee` whose caller's static callees didn't already carry the subject's bit, it **re-runs `rta.AnalyzeBitmask` from scratch for that single subject in isolation** (`singleSeeds`, lines 206–234)!
3. **Dual Provenance BFS Walkers ([`provenanceReachable`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L3529-L3597) & [`provenanceReachableStartup`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L2969-L3033))**:
   - Even within a single subject's RTA run, an `init` function in an imported package can instantiate types or reference functions. To filter out functions only reached via dead/unreferenced `init` paths, `provenanceReachable` and `provenanceReachableStartup` perform a BFS from roots using `functionValueRefs` (`attribution.go:3496–3527`) and `narrowedTargets`.
   - **Consolidation defect**: `provenanceReachable` (lines 3529–3597) and `provenanceReachableStartup` (lines 2969–3033) are **two copy-pasted 65-line BFS functions** with identical structure, differing only in whether `callee == dropTarget` is skipped and whether `valueRefOutsideInit` defers `init`-only references in `pendingByParent` until `callee.Pkg` becomes `livePkg`.
4. **Caller Reference Summary ([`callerReferenceSummary`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L728-L775), [`summarizeCallerReferences`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/attribution.go#L1873-L2129))**:
   - Precomputes a program-wide index of:
     - `callSites`: where each `*ssa.Function` is passed as a value or stored into a local cell / slice / struct field that is later called.
     - `makeClosures`: every `*ssa.MakeClosure` site for each anonymous function.
     - `structFieldStores` / `structWholeStores` / `structPoisoned`: every `*ssa.FieldAddr` store and whole-struct `*ssa.Store` to a user `*types.Named` struct across `prog`.
   - Cached in a global mutex-protected map `summaryCache` (`attribution.go:912–915, 1884–1889`) keyed by `(*ssa.Program, audited)` that wipes the entire map when `len(summaryCache) >= 8`.

### 4.4 Globals and `init` Functions

Global variable state and package initialization are analyzed through three separate mechanisms across `analyzer.go`, `attribution.go`, and `freshpath.go`:

3. **Whole-Program Global Mutation Scan ([`programMutatedGlobals`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/closure/freshpath.go#L2618-L2670))**:

## 5. Accumulated Trial-and-Error Special Cases & Consolidation Opportunities
