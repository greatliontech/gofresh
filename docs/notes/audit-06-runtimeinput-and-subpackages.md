## 3. Deep Architectural Audit of `runtimeinput` (5,101 Lines)

### 3.1 End-to-End Interaction Model

`runtimeinput` implements two layered APIs over a single underlying verification model:

1. **The Producer Facade (`ProducerFrame` / `ProducerIngest` / `Roots` / `FileInputEligibility`)**:
   - **Pre-spawn (`CaptureProducerFrame` in [`producer.go:73-93`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/producer.go#L73-L93))**: Resolves `treeRoot` and `pkgDir` via `filepath.EvalSymlinks`, verifies `pkgDir` is inside `treeRoot`, allocates a fresh `outcome.Span` pointer identity, and calls `CaptureBracket` over `[pkgRel, opts.BracketPaths...]` with `[".git", opts.ExcludedPaths...]` excluded.Any failure fails closed into `ProducerFrame{reason: ...}` rather than returning an error, so the caller can still run the process and call `Observe`, which will produce a properly sealed incomplete `Observation`.
   - **Process execution & completion (`ProducerFrame.Completion` in [`outcome.go:29-35`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/outcome.go#L29-L35))**: Binds the process identity, normalized NUL-joined environment SHA-256, `span`, `Root`, and `PkgDir` into an `outcome.Binding` inside `CompletionReceipt`. Simultaneously, the analysis view (`gofresh.Snapshot`) uses `ProducerFrame.OutcomeBinding` to issue an opaque `OutcomeSupport` (`internal/outcome.Support`) over the same `outcome.Binding`.
   - **Post-spawn ingest (`ProducerFrame.Observe` / `ObserveInputs` in [`producer.go:164-220`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/producer.go#L164-L220))**:
     1. Validates `in.Completion` against `f.OutcomeBinding(in.Identity, in.Env)`.
     2. If `requireOutcomes` (`Observe`), validates `in.Outcome.Reason(binding)` and checks `environmentLog(ctx, log)` (requiring that the testlog contain only `# test log` and `getenv` lines for `gofresh/immutable-environment@1`).
     3. Reads the testlog file via `readProducerLog` (using `captureReader` to check `ctx.Err()` before and after every `Read` call, and verifying the `# test log\n` header).
     4. Validates `PWD` in `in.Env` against `f.PkgDir` via `producerPWDProblem`.
     5. Resolves toolchain/cache/temp classification roots once per `(pkgDir, env)` coordinate via `resolveRoots` (`roots.go:110-131`), backed by `Roots.memo` (`gotool.RunMemo[*gotool.EnvReader]`). Guard roots (`GOROOT`, `GOMODCACHE`, `GOCACHE`) that overlap `treeRoot` degrade to `""`; temp roots (`ScratchRoot`/`TMPDIR` and `GOTMPDIR`) that lie inside `treeRoot` degrade to `""`.
     6. Assembles `TestLogOption`s via `producerClassificationOptions` (always excluding `"."` and `".git"` at ingest) and delegates to `fromTestLog`.
   - **Explicit-file preflight (`FileInputEligibility` in [`file_eligibility.go:65-162`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/file_eligibility.go#L65-L162))**: Re-runs the same environment normalization, `producerPWDProblem`, `resolveRoots`, and `producerClassificationOptions` pipeline to classify a single clean, symlink-free regular file into `RawFileInput`, `ElidedFileInput`, `ProjectedFileInput`, or `UnverifiableFileInput`.

2. **The Core Bracket, Testlog, Motion-Tracking, and Manifest Engine (`FromTestLog` / `Bracket` / `pathFacts` / `State` / `Observation`)**:
   - **Bracket capture & motion tracking (`CaptureBracket`, `fingerprintBracketRoot`, `pathFacts`, `movedBracketRoot`)**:
     - Instead of relying on OS-specific file watchers (like Linux `inotify`), span movement is tracked deterministically and portably by recording fine-grained `pathFacts` ([`pathfacts.go:40-43`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/pathfacts.go#L40-L43)) during both the pre-run `CaptureBracket` pass and the post-ingest `Bracket.revalidate` pass.
     - During `hashPath` and `chainResolveObserved`, every filesystem observation is recorded as an independent fact in `root.facts`:
       - `namespaceFact`: non-followed `lstat`/`DirEntry.Type()` mode type (e.g. `"type 0"` for regular, `"type 8000000"` for symlink, `"type 2000000"` for FIFO) or `"missing"`.
       - `linkFact`: `os.Readlink` target string.
       - `resolutionFact`: final resolved path of `chainResolveObserved`.
       - `followedStatFact`: SHA-256 of `os.Stat` metadata (`size`, `mode`, `mtime`, `isDir`, or `dir mode` for directories) or `"missing"`.
       - `namespaceStatFact`: SHA-256 of `d.Info()` during `dirHashFiltered`.
       - `contentFact`: SHA-256 of regular file contents.
       - `machineFact`: `MachineFacts.Fingerprint()` for allowlisted `/proc` machine-identity files (`key.path == ""` so machine projection facts compare across all machine-fact roots).
       - `listings`: per-directory `directoryListing{offset, names, complete}` records.
     - Crucially, `movedBracketRoot` ([`pathfacts.go:156-282`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/pathfacts.go#L156-L282)) separates **demonstrated movement** (`BracketMoved = true`, which is a non-waivable guard failure) from **knowledge gain/loss** (`Unverifiable = true`, e.g., `chmod 000` on an ancestor directory mid-run without mutating the underlying file). A conflict occurs if and only if:
       1. The same `pathFact` key has two distinct scalar values across roots or endpoints (including within a single pass);
       2. A `namespaceFact != "missing"` or directory-listing entry name coexists with `namespaceFact == "missing"` at the same path; or
       3. A complete directory listing omits a name that was observed present in that directory (unless the child identity is excluded by `b.exclusions`).
   - **Testlog parsing & 6-way admission filter (`fromTestLog` in [`runtimeinput.go:862-1220`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/runtimeinput.go#L862-L1220))**:
     - Tracks `cwd` (initially `packageDir`) and `cwdChanged` (set on any `chdir`).
     - For `open` and `stat` operations, when `!ambiguousParent && !relativeAfterChdir`, checks 5 recordless admission classes before recording:
       1. `guardCovered(p, guardRoots, guardMemo)`: `p`, its `chainResolve` target, and every traversed symlink lie inside `GOROOT`, `GOMODCACHE` (excluding `cache/`), or `GOCACHE` (excluding `fuzz/`), and the target exists.
       2. `!moduleInterior(p) && ephemeralRoot(p, ephemeralRoots)`: `p` is the lexical or resolved root of `TMPDIR`/`ScratchRoot` or `GOTMPDIR`.
       3. `!moduleInterior(p) && ephemeralScratch(p, ephemeralRoots, resolvedModule, scratchMemo)`: `p` is under an ephemeral root, `os.Lstat(p)` is `ENOENT` at ingest, and `nearestExistingAncestorResolved(p)` resolves inside an ephemeral root and outside `resolvedModule`.
       4. `ephemera.admits(p, ephemeraMemo)` (`bracketEphemera` in `bracket.go:842-894`): `p` is strictly inside a declared `ScratchNamespace` under a `pathRel` bracket root, not excluded, neither `offset` nor `matched.childOffset` was in `root.members` at bracket capture, `os.Lstat(p)` is `ENOENT` at ingest, and `nearestExistingAncestorResolved(p)` resolves under `root.resolved`.
       5. `nullSink(p)`: `p == os.DevNull`.
     - Next checks `cfg.excludesRaw(moduleDir, p)`.
     - For `stat` only: if `p` is an unambiguous external absolute non-volatile path whose `os.Stat` is a directory or `ENOENT`, records `id` in `m.Paths` with `existenceBound[id] = true` (skipping the `stat metadata input` unverifiable seal and skipping bracket coverage).
     - Otherwise calls `classifyPath(moduleDir, p)` and ` upsertPath`: `open` records `Metadata: false` (content + mode + size, no mtime); `stat` sets `Metadata: true` (adds mtime) and adds `"stat metadata input: ..."` unless `bracketStatRoots.covers(id)` is true.
   - **Resolution-based bracket coverage & revalidation (`fromTestLog` lines 1144–1209)**:
     - Every recorded `m.Paths` entry (except `machineProjected(id)` and `existenceBound[id]`) must pass `coverage.covers(id)` (`bracket.go:545-579`), which checks that `chainResolve` of `id` lands inside a declared root and traverses no symlink outside declared roots.
     - Calls `stateFromManifest` (computing per-entry digests and combined `manifestDigest`), then `cfg.bracket.revalidate(ctx, moduleDir)`, and seals the `Observation` with process provenance (`processObservation{process, origin, view}`).

### 3.2 Structural Tangling & Concrete Duplications Inside `runtimeinput`

#### Finding RI-1 (High — Performance & Redundant I/O): `fromTestLog` Double-Hashes Every File and Directory When the Bracket Moves or Is Unverifiable
- **Location**: [`runtimeinput/runtimeinput.go:1179-1209`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/runtimeinput.go#L1179-L1209) and [`stateFromManifest` (`L1498-L1554`)](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/runtimeinput.go#L1498-L1554).
- **Evidence**:
  At line 1179, `fromTestLog` calls `st, err := stateFromManifest(ctx, m, moduleDir, normalized)`. This walks and SHA-256 hashes every file and directory in `m.Paths` and populates `m.Env[i].Digest` and `m.Paths[i].Digest`.
  Then at line 1186, `cfg.bracket.revalidate(ctx, moduleDir)` runs (which must execute after the manifest's last input read per `REQ-inputs-value-binding`).
  When `!unchanged` (the bracket moved or had an unverifiable root), lines 1190–1208 mutate only `m.BracketMoved` and `m.Unverifiable`, and then call `stateFromManifest(ctx, m, moduleDir, normalized)` **a second time** at line 1206!
  Because `m` was passed by value to the first `stateFromManifest` call, the caller's `m.Env[i].Digest` and `m.Paths[i].Digest` slices were not even retained, forcing the second `stateFromManifest` call to re-open, re-walk, and re-hash every single observed file and directory on disk!
- **Fix**: Split `stateFromManifest` into (1) `populateManifestDigests(ctx, &m, moduleDir, normalized)` (which hashes `m.Env` and `m.Paths` once) and (2) a pure in-memory `finalizeManifestState(m, pathUnverifiable, pathReason) (State, error)` (which sorts `m`, encodes JSON+base64url, and computes `manifestDigest(m)`). When `!unchanged`, update `m.BracketMoved` and `m.Unverifiable` and call `finalizeManifestState` in memory with zero additional filesystem I/O.

#### Finding RI-2 (High — Bug Trap / Duplicated Logic): `underPath(p, root)` vs `contains(dir, path)` Have Opposite Parameter Orders and Divergent `/` Root Handling
- **Location**:
  - [`underPath(p, root string) bool`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/runtimeinput.go#L1898-L1900) in `runtimeinput.go`:
    ```go

    ```
  - [`contains(dir, path string) bool`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/roots.go#L154-L162) in `roots.go`:
    ```go
    func contains(dir, path string) bool {
        if dir == path {
            return true
        }
        if dir == string(filepath.Separator) {
            return filepath.IsAbs(path)
        }
        return strings.HasPrefix(path, dir+string(filepath.Separator))
    }
    ```
  - Also compare [`pathOffset(root, p string) (string, bool)`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/runtimeinput/bracket.go#L753-L762) in `bracket.go` (`(root, p)` order, does not handle `root == "/"`).

Both are called in `file_eligibility.go` and `runtimeinput.go`! Furthermore, `underPath` fails when `root == "/"` (`root + "/"` becomes `"//"`), whereas `contains` handles `dir == string(filepath.Separator)`.

### 4.2 `internal/buildflags`: `Validate` Ignores Its Own Package's `buildflags.Fields` Parser

- **Finding SUB-2 (Medium — Split-Brain Flag Splitting Within `internal/buildflags`)**:
  - **Location**: [`internal/buildflags/buildflags.go:28-33`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/internal/buildflags/buildflags.go#L28-L33) vs [`internal/buildflags/quoted.go:11-34`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/internal/buildflags/quoted.go#L11-L34).
  - **Evidence**:
    `internal/buildflags/quoted.go` defines `Fields(text string) ([]string, error)`, which implements the Go command's exact quoted-field splitting grammar for `GOFLAGS` (where a leading `'` or `"` delimits one whole field with literal contents, and unterminated quotes return an error).
    Yet `buildflags.Validate` in `internal/buildflags/buildflags.go:28-29` splits `GOFLAGS` using `strings.Fields(goFlags)` followed by `flag = strings.Trim(flag, "\"'")`!
    Consequences of this split-brain implementation inside the same 2-file package:
    1. **False positive**: If `GOFLAGS` contains a quoted flag whose value has whitespace followed by `-overlay=...`, e.g. `GOFLAGS="-ldflags=-X=pkg.msg=' -overlay=x'"` or `GOFLAGS="'-gcflags=-D=foo -overlay=bar'"`, `strings.Fields` splits on the interior whitespace and `Validate` falsely rejects it as an `-overlay` flag, whereas `go` and `buildflags.Fields` treat the quoted string as a single flag value.
    2. **Malformed `GOFLAGS` handling**: An unterminated quote in `GOFLAGS` is rejected by `buildflags.Fields` (and by the `go` command), whereas `strings.Fields` + `strings.Trim` silently strips the leading quote.
  - **Fix**: Call `buildflags.Fields(goFlags)` inside `buildflags.Validate` instead of `strings.Fields` + `strings.Trim`.

### 4.4 `guard` vs. `resident`: Duplicate `/proc/meminfo` Kibibyte Parsing

- **Finding SUB-4 (Low — Divergent `/proc/meminfo` `MemTotal` Parsers in `guard` and `resident`)**:
  - **Location**: [`guard/machine_linux.go:169-186`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/guard/machine_linux.go#L169-L186) (`parseMemTotal`) vs [`resident/resident.go:133-163`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/resident/resident.go#L133-L163) (`kibibyteLines`) and [`resident/host.go:31-37`](file:///home/nikolas/repos/github.com/greatliontech/gofresh/resident/host.go#L31-L37) (`parseMeminfo`).
  - **Evidence**:
    `resident.kibibyteLines` strictly validates `len(fields) == 2 && fields[1] == "kB"` and guards against uint64 overflow (`n > math.MaxUint64/1024`) and `MemTotal == 0`.
    `guard.parseMemTotal` checks only `len(fields) >= 1` (ignoring the unit field `fields[1]` and any trailing tokens) and does `kb * 1024` without overflow or zero checks.
  - **Fix**: Harden `guard.parseMemTotal` to require `len(fields) == 2 && fields[1] == "kB"`, `kb > 0`, and `kb <= math.MaxUint64/1024` so `guard`'s machine identity parser is as strict as `resident`'s.
