# An in-module generated package's init-once writes have no discharge — the vouch is dependency-only and a directive cannot live in generated code

Filed from tugboat (2026-09-30), uncommitted for the gofresh agent's
triage.

Observed: after tugboat collapsed its own shared status-error var
(the errInboundClosed escape, restructured to a per-call constructor),
the next shared-dynamic-state culprit on every grpctransport witness
(~100 subjects) is the generated protobuf descriptor:
`transport/grpctransport/transportpb.File_transport_grpctransport_transportpb_transport_proto
is mutated (dischargeable by restructuring the state, or by the
//gofresh:single-subject directive on the declaration under the
caller's single-subject attestation)`. The writes are protoc-gen-go's
generated init exactly: the descriptor assigned from the type builder,
the message-info slice its builder fills, the go-types and dep-index
tables cleared after use — once, at package init, by nothing
afterwards.

Why neither named channel applies: the declaration is generated
(`buf generate` rewrites transport.pb.go), so a source directive on
it does not survive regeneration and cannot be maintained; the state
cannot be restructured — protoc-gen-go owns the shape. The vouch
channel (`dynamic_state_vouches`, "a version-pinned dependency
variable accepted as stable after initialization") is exactly this
case in nature — tugboat added the four variables to its policy and
both vouch files and the reason did not move — but the spec scopes it
to version-pinned dependencies only (closure.md: "version-pinned
dependencies only, the acceptance …"; "a vouch crosses the
version-pinned line because dependency …"), so an in-module generated
package is the one place with init-once writes and no channel at all.

Need (need-level): a discharge for in-module generated init-once
state. Candidates the spec's own shape suggests: extend the vouch to
in-module variables under an attestation (the same audit the
dependency vouch rides — the writers enumerated, none past init);
or a generated-package admission keyed on the generator's marker
(`// Code generated by protoc-gen-go. DO NOT EDIT.`) that audits the
generated init pattern once per generator version, as the
version-pinned module audits do. Which is gofresh's to derive;
tugboat carries the ~100 uncacheable rows as a serving cost until
then and records the attempted vouch in its commit history.
