# Multi-GiB `testlog` Whole-File Allocation, Tracked `chdir` Sealing/Elision & Leaked Test Overlay Temp Dirs

- **Status:** Open
- **Governing contract:** [`docs/specs/runtime-inputs.md`](../specs/runtime-inputs.md) (`REQ-inputs-observation-disposition`, `REQ-inputs-path-congruence`, `REQ-inputs-exclusions`, `REQ-inputs-unbounded`), [`docs/specs/evidence.md`](../specs/evidence.md) (`REQ-fresh-built-unit`, `REQ-fresh-final-evidence-selection`), [`docs/specs/closure.md`](../specs/closure.md) (`REQ-closure-observability-toolchain-key`)
- **Lands:** Chunk 5 in [`docs/plans/plan.md`](../plans/plan.md)

## Problem

1. **Whole-File `os.ReadFile` + `bytes.Split` on Multi-Hundred-MiB to `2.1 GiB` `testlog.txt` Files**
   - `readProducerLog` ([`internal/runtimeinput/producer.go`](../../internal/runtimeinput/producer.go) line 350) and `fromTestLog` ([`internal/runtimeinput/testlog.go`](../../internal/runtimeinput/testlog.go) lines 342–350) read the entire `GODEBUG=testlogfile` output into memory via `os.ReadFile` and split it into a `[]string` / `[][]byte` slice (`8.5M` to `25M` lines on integration suites producing `957 MiB`–`2.1 GiB` testlogs), driving peak process RSS up to `11.5 GiB` and running `filepath.Clean` + classification across millions of duplicate `(cwd, op, arg)` lines (`24s–26s` per large binary).

2. **`case "chdir":` Omits `elidesUnambiguous`, Leaves `cwdChanged` Sticky After `t.Chdir` Cleanup, and Unconditionally Seals `"working-directory change"` (`internal/runtimeinput/testlog.go:483-510`)**
   - When tests use standard `t.Chdir(t.TempDir())` (which creates a scratch directory under `testTempRoot`, `chdir`s into it, and registers a cleanup `os.Chdir(packageDir)` at test exit), three mechanisms in `fromTestLog` ([`internal/runtimeinput/testlog.go`](../../internal/runtimeinput/testlog.go) lines 386, 410–417, 483–510) reject the entire batch under `assume_pure: false`:
     1. Unlike `open` and `stat` (`lines 392, 417`), `case "chdir":` (`lines 493–507`) omits `classifier.elidesUnambiguous(p)` and inserts `/tmp/Test.../001` into `m.Paths` (`line 501`), failing `coverage.covers(id)` (`134` subjects in `gomutant/internal/cmd`).
     2. `cwdChanged = true` (`line 509`) stays sticky even after `t.Chdir`'s cleanup logs `chdir <packageDir>` restoring `cwd == packageDir`, causing every subsequent test in the binary that opens/stats a relative path while `cwd == packageDir` to fail with `relative runtime input after working-directory change` (`552` subjects in `gomutant`).
     3. Even when `t.TempDir()` is elided and `cwd == packageDir` is restored, `case "chdir":` unconditionally records `addUnverifiable(&m, unverifiableSeen, "working-directory change")` (`lines 494, 503`), implementing the current blanket rule in [`docs/specs/runtime-inputs.md`](../specs/runtime-inputs.md) lines 547–557 (`REQ-inputs-observation-disposition`) and lines 650–652 (`REQ-inputs-exclusions`). Without refining that contract for tracked, unambiguous, restored `chdir` excursions, all `134 + 552` subjects remain uncacheable whenever `assume_pure` is `false`.

3. **Leaked `/tmp/gofresh-inmem-pkg-*` Directories from `internal/testenv` Defeat `ephemeralScratch` (`internal/testenv/frontend.go:806-816`, `internal/runtimeinput/scratch.go:393-395`)**
   - `ParseAndTypecheckDAGWithStdlibErr` ([`internal/testenv/frontend.go`](../../internal/testenv/frontend.go) lines 806–816) allocates `os.MkdirTemp("", "gofresh-inmem-pkg-*")` and appends it to `sharedOverlayDirs` expecting callers to invoke `CleanupShared()`. Callers that omit `CleanupShared()` leak `/tmp/gofresh-inmem-pkg-*` directories in `/tmp` (`2,974` leaked directories observed).
   - Whenever any test or directory scan stats `/tmp` entries while those directories still exist on disk (`os.IsNotExist(err) == false` at `Unit.Close`), `ephemeralScratch` ([`internal/runtimeinput/scratch.go`](../../internal/runtimeinput/scratch.go) lines 393–395) returns `false` and bakes `/tmp/gofresh-inmem-pkg-*` entries into `Fingerprint.RuntimeInputs`.

## Soundness Constraints & Resolution Scope

1. **Streaming `testlog` Reader**: Stream `testlog.txt` from an `io.Reader` / `*os.File` with bounded line buffering (preserving exact malformed-line and truncation refusal semantics) and deduplicate `(cwd, op, arg)` tuples per tracked `cwd` before path cleaning and classification.
2. **Premise-Gated `testing.T.Chdir` Excursion Contract (`docs/specs/runtime-inputs.md`, `docs/specs/evidence.md`, `docs/specs/closure.md`, `toolchain`, `testlog.go`)**:
   - `testlog.txt` alone cannot distinguish a sequential `testing.T.Chdir` excursion from raw `os.Chdir` / `(*os.File).Chdir` calls racing with `t.Parallel()` goroutines, nor can `final cwd == packageDir` alone prove every excursion was balanced on `NormalCompletion` of a failing test binary (`REQ-fresh-built-unit` and `REQ-fresh-final-evidence-selection` in [`docs/specs/evidence.md`](../specs/evidence.md) admit ordinarily completed failing test binaries, where an aborted `Chdir` before `Cleanup` registration followed by a later test's restored `t.Chdir` could still end at `packageDir`).
   - Update `REQ-inputs-observation-disposition`, `REQ-inputs-path-congruence`, and `REQ-inputs-exclusions` in [`docs/specs/runtime-inputs.md`](../specs/runtime-inputs.md) and `REQ-closure-observability-toolchain-key` in [`docs/specs/closure.md`](../specs/closure.md):
     1. **Toolchain audit premise**: Alongside `os.Chdir` (already verified in `audit_os_core.go` to log `testlog.Open(dir)` on `syscall.Chdir` error and `log.Chdir(wd)` via `Getwd()` only on success), verify `(*os.File).Chdir` (`Fchdir` logging `log.Chdir(wd)` via `Getwd()` only on success) and `testing`'s `(*T).Chdir`, `(*B).Chdir`, and `(*common).Chdir` in `internal/closure/internal/toolchain` (proving `checkParallel()` rejects parallel callers, `oldwd` is captured before `os.Chdir`, and `Cleanup` restores `oldwd.Chdir()` in LIFO order and panics if restoration fails).
     2. **Binary-graph premise**: Permit tracked `chdir` unsealing and in-excursion relative-path resolution **only** when the producing test binary's non-stdlib package graph never directly reaches raw `os.Chdir`, `(*os.File).Chdir`, `syscall.Chdir`, `syscall.Fchdir`, or `golang.org/x/sys/unix.Chdir` (`Fchdir`) outside `testing`'s `(*T).Chdir` / `(*B).Chdir` / `TB.Chdir`. When raw `Chdir`/`Fchdir` is reachable in the binary, retain the unconditional fail-closed `"working-directory change"` and sticky `relativeAfterChdir` seal.
     3. **Balanced LIFO stack & log-level invariants under the premise**: Require `pwdTruthful` at start, treat any relative or unresolved `chdir` target in `testlog.txt` as sticky fail-closed `cwdAmbiguous = true`, track `chdir` transitions against a balanced LIFO restoration stack rooted at `packageDir` (so any excursion aborted before `Cleanup` registration — even on a `NormalCompletion` failing binary followed by a later test's `t.Chdir` — fails stack balance and seals `"working-directory change"`), resolve in-excursion relative `open`/`stat` operands against the current clean absolute `cwd`, elide unambiguous scratch/temp-root `chdir` targets (`classifier.elidesUnambiguous(p)`), and require non-elided `chdir` targets and resolved relative reads to satisfy normal bracket coverage and manifest hashing. Also account for `(*common).Chdir`'s `c.Setenv("PWD", dir)` / `testing.Chdir` classification (`internal/closure/effects.go` and `observability.go`) for the `t.Chdir`-calling subject vs. its sibling batch subjects.
3. **`internal/testenv` Overlay Cleanup**: Avoid materializing `/tmp/gofresh-inmem-pkg-*` on disk when virtual paths suffice or ensure `ParseAndTypecheckDAGWithStdlibErr` / test suites deterministically remove every created directory on teardown.
