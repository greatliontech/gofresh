# Repository Directives

## Working Notes & Compaction Defense (`docs/notes/`)

1. **Per-Chunk Lifecycle:** Maintain one working-notes file (`docs/notes/<chunk-slug>.md`) per active chunk — never a multi-chunk append-only log. Read `docs/plans/plan.md` (when present), any active `docs/notes/<chunk-slug>.md`, and scheduled `docs/issues/` (when present) first after startup or compaction.
2. **Continuous Standalone Updates:** Record user alignments, root-cause diagnoses, soundness/performance audits, hypotheses, rejected dead ends, and review dispositions in `docs/notes/<chunk-slug>.md` as they occur, committing standalone `docs(notes)` / `docs(plan)` updates without sweeping in uncommitted code.
3. **Close-Out Promotion & Deletion:** Keep chunks isolated on the working tree. Promote contracts to `docs/specs/`, mechanism rationale to package/module doc comments, local constraints to code comments, and cross-chunk discoveries or scheduled deferrals (`Lands:`) to `docs/issues/<slug>.md` or `docs/plans/plan.md` **before** final review convergence so they are reviewed alongside `docs/notes/<chunk-slug>.md`, then delete `docs/notes/<chunk-slug>.md` in the chunk close-out commit once review reaches `ZERO FINDINGS`, recording process reasoning in the commit message (`docs/notes/` stays empty between chunks).

## Scope, Authority & Architecture

1. **5-Repo Autonomous Ownership:** Full ownership of specs, code, commits, and direct `git push` (without asking for confirmation) spans `go-x-tools`, `gofresh`, `gomutant`, `stipulator`, and `pew` (`godst` remains outside modification scope unless explicitly requested). Derive internal representation, refactoring, test-harness, and sequencing decisions from correctness and total work; escalate only genuine non-derivable external contract forks.
2. **Toolchain Flavor Invariance:** Every analysis, guard, build, and test across the 5 repos must behave identically under both `godst` and vanilla Go toolchains, with zero flavor-specific or Go-version-list hardcoding.
3. **Zero Third-Party Allowlists or Hardcoding:** `gofresh` analyzes arbitrary user repositories and their transitive dependencies, not just our own tools. Never hardcode third-party module, package, symbol/field, or semver allowlists (`VersionListing`) across `closure`, `dynstate`, or `auditset`. Analyze Go constructs (startup dead-branch pruning on unmutated zero globals, memoizers, interface/parameter closure, sentinel globals) and non-toolchain `.s` assembly on disk per `TEXT` symbol (`RODATA` globals, `(SB)` symbol discipline, no syscalls/traps/clocks/RNGs, decoded ISA feature queries, carrier-free Go signatures) mechanically from first principles; require caller authority (`//gofresh:pure` or dependency-boundary vouches) only for genuine non-derivable external blindspots.
4. **IR Normalization & Anti-Thrash Circuit Breaker:** Build dataflow, CFG, and provenance analyses on normalized IR (e.g., `flowir`, `go/ssa`, or dedicated syntax/assembly CFG kernels) rather than bespoke raw-`go/ast` switches, keeping non-test, non-generated production files cohesive (`<= ~1,050` LOC; preserve stipulator-bound symbol homes on same-package splits or run `stipulator retarget`, and schedule dedicated chunks for pre-existing monoliths rather than violating chunk isolation). If adversarial review on a mechanism exceeds 3 rounds without converging or an unscheduled production file grows past `~1,050` LOC, stop symptom-patching and refactor onto normalized IR, a cleaner lattice, or cohesive same-package splits before another review round.
5. **Stipulator Static-Records-Only Flow Before Release & Upgrade:** Because the installed `stipulator` binary links a released `gofresh`, never run witness-executing `stipulator` commands (`check`, `gate`, `verify` without `--no-test`, `prune` without `--no-test`/`--dangling`, `gap --list`) while developing unreleased `gofresh` or `stipulator` witness-execution fixes. Until an updated `gofresh` release is tagged (via CI) and rebuilt/installed into `stipulator` (or `stipulator` is rebuilt/installed for `stipulator`-only fixes), use only static commands (`compile`, `pin`, `bind`, `unbind`, `retarget`, `dispose`, `attest`, write-mode `gap`, `prune --no-test`/`--dangling`, and `verify --no-test --view bindings`), verifying every bound `REQ-` row is `current` and `resolved` (`0` stale, rehash-pending, unpinned, moved, or unresolved rows, as `verify --no-test` exits non-zero only on structural `Problems`) while running affected witness `Test*`/`Fuzz*` functions via `go test`. Run full `stipulator check` only after the updated `gofresh` release is tagged and linked into a rebuilt/installed `stipulator` binary (or after rebuilding/installing `stipulator` for `stipulator`-only changes).

## Diagnostic Tracing, Testing & Oracles

1. **Proactive `internal/trace` Provenance:** Across `gofresh`'s trace domains (`toolchain`, `closure`, `dynstate`, `runtimeinput` [including `guard`], `cache`, `view`, `session`), emit `trace.Emit` events at classifier, mutation/escape attribution, capability promotion, fixed-point trigger, and discharge refusal boundaries carrying `reason` plus applicable symbol/type and source `pos`, gating formatting and `Position` lookups behind `trace.Enabled`/`trace.AnyEnabled` for zero disabled cost. Diagnose failures via `GOFRESH_TRACE=<domain>:<target>` and `trace.Recorder` — never via temporary print or `go test -overlay` scripts; when trace output lacks a causal link, add the `trace.Emit` event permanently first.
2. **Orthogonal Case-Space Matrices & Harnesses (Cases, Not LOC):** Design tests and reusable hermetic harnesses (`internal/testenv` or subsystem harnesses) alongside every mechanism, covering orthogonal input dimensions (type/AST/CFG/SSA combinators, execution modes, cold/warm cache and cross-mode replay states, adversarial inputs, and positive/negative controls) via compact parameterized tables.
3. **Properties, Fuzzing & Causal/Mutation Oracles:** Accompany static analyses and predicates with compositional `pgregory.net/rapid` properties checked against independent semantic, execution, or metamorphic reference oracles; pair parsers/scanners, lowerings, and codecs with `testing.F` fuzz targets seeded from boundary cases asserting crash-freedom, determinism, and round-trip/oracle invariants; verify every new or changed testable invariant kills targeted `gomutant ephemeral` probes (`0` non-equivalent survivors — strengthen tests or demonstrate semantic equivalence); and assert exact causal refusal/culprit reasons on negative/revocation tests (via `trace.Recorder` on `ctx`-traced `gofresh` paths — threading `ctx` where needed — or structured causal outputs on contextless, leaf, or cross-repo APIs) so tests cannot pass via an unintended fallback.
